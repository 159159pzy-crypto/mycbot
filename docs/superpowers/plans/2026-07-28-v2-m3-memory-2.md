# V2-M3 Memory 2.0 Implementation Plan

**Goal:** Upgrade memory from append-only vector recall into a privacy-enforced,
temporally versioned, hybrid-retrieved system that can merge facts, inject bounded
core memory, self-edit through policy-controlled tools, consolidate during maintenance,
and flush facts before prompt history truncation.

**Architecture:** `MemoryItem` keeps one temporal truth model: semantic replacement or
deletion sets `invalid_at` and optional `invalidated_by`; `revoked_at` remains reserved
for user/operator privacy revocation and hard-forget paths. Candidate extraction feeds a
separate merge pipeline. The pipeline retrieves same-scope/same-privacy candidates,
accepts only validated ADD/UPDATE/DELETE/NOOP decisions whose target ids came from that
retrieval, and applies each decision atomically with an operation audit row. Runtime
recall uses pgvector and `pg_trgm` rankings fused with deterministic RRF after the same
scope, privacy, validity, invalidation, and revocation filters. Core blocks are bounded
rows injected every turn; their tools use the existing capability and approval gates.
Maintenance consolidation and pre-truncation flush both reuse the merge pipeline and the
M1 memory-purpose model route.

**References checked 2026-07-28:** current mem0 memory-manager prompt and ADD/UPDATE/
DELETE/NONE semantics; current Graphiti `valid_at`/`invalid_at`, hybrid BM25/cosine
recipes and RRF implementation; current Letta core-memory blocks plus append/replace
tools and sleeptime persona; current OpenClaw pre-compaction memory-flush documentation.
These are mechanism references only; implementation remains independent.

- [x] Add RED contract tests for `invalid_at`/`invalidated_by`, operation decisions,
  core-block labels and token budgets.
- [x] Add migration 0009 with temporal backfill, `pg_trgm`, operation/recall audit tables,
  core blocks, constraints, and downgrade coverage.
- [x] Reserve revocation for privacy/user actions and use invalidation for semantic
  update/delete/expiry/decay.

## Task 2: Atomic extraction and merge pipeline

- [x] Add RED tests for same-scope/privacy candidate lookup and strict ADD/UPDATE/DELETE/
  NOOP parsing, including rejection of arbitrary target ids.
- [x] Apply UPDATE as insert-successor plus invalidate-predecessor in one transaction;
  apply DELETE as invalidation; audit every decision including NOOP.
- [x] Ensure `/forget`-revoked rows cannot be update targets or revived through the
  successor path; keep extraction failures non-fatal.

## Task 3: Hybrid retrieval and provenance audit

- [x] Add pgvector and trigram top-k queries under identical SQL privacy/scope/time filters.
- [x] Fuse rankings with deterministic RRF, expose vector/text ranks to the service, and
  record selected/vector/text ids with a query hash rather than raw query text.
- [x] Add tests for Chinese names, slang/abbreviations, vector-only hits, text-only hits,
  deterministic ordering, and direct-vs-group privacy behavior.

## Task 4: Core blocks and self-edit tools

- [x] Add persona and per-subject user-profile core blocks with enforced token budgets,
  versions, and operation audit.
- [x] Inject visible core blocks on every non-ephemeral turn before retrieved memories.
- [x] Register `memory_append` and `memory_replace` as built-in tools behind
  `memory.write` capability and configurable `approval_required` policy.

## Task 5: Sleep consolidation and pre-truncation flush

- [x] Add a bounded, once-per-interval consolidation job that reviews recent dialogue and

- [x] Add history partitioning so messages dropped by count/token pressure are flushed
  through the memory-purpose model before prompt assembly, with Redis per-conversation
  debounce and hard message/token caps.
- [x] Keep both jobs optional, cancellation-safe, failure-isolated, and budget bounded.
